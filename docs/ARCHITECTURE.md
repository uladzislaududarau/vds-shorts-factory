# Архитектура

Один FastAPI-процесс на loopback обслуживает API и production frontend. Vite development запускается отдельно по желанию, `/api` проксируется на 8765. React периодически обновляет серверное состояние, без выдуманных counters.

SQLite WAL, foreign keys и транзакции: Sources → RightsMetadata; Transcripts; Analysis с ключом кэша; Clips → Scores, Segments, Projects; Jobs → RenderTasks; Settings; Usage. Миграции идемпотентные, версия хранится в `migrations`. Текущая версия схемы 1.

Очередь: три управляющих потока, максимум одна analysis и одна render задача одновременно; отдельные семафоры Whisper/AI/FFmpeg = 1. FFmpeg/PySceneDetect/Whisper запускаются без shell в собственных группах процессов. Pause/Cancel проверяется каждые 200 мс и завершает только группу данной задачи. Сетевой запрос SDK может завершаться до своего timeout перед остановкой. Завершение стадии записывается в checkpoint, файлы транскрипции и AI-кэша заменяются атомарно.

`IMPORT → PROBE/THUMBNAIL → AUDIO → MLX/WORDS → SCENES → ANALYSIS → SCORES → PROJECT → CROP/CAPTIONS → RENDER → QC → ZIP`.

Источники идентифицируются SHA-256. Транскрипции кэшируются с моделью и языком. Ключ анализа включает хэш источника, текст, модель/режим и параметры отбора. AI-запросы дополнительно кэшируются по модели, схеме и содержимому запроса. Повторные запросы не оплачивают кэшированный результат. Монтажные проекты и render jobs содержат снимок плана и revision. Завершённый старый render помечается устаревшим, если за время его работы план изменился.

Статус Running означает исполнение; `stage` конкретизирует Transcribing/Analyzing/Scoring/Preparing/Rendering/QC. Проценты — прогресс по завершённым стадиям, не точный процент кадров или токенов. Jobs переживают перезапуск, аварийные Running становятся Queued, Paused остаются Paused.

Защита: localhost Host allowlist, проверка Origin, обязательный non-simple client header на мутациях, отсутствие CORS, закрытые media пути по ID, проверка типа через FFprobe, whitelist расширений, потоковая запись с лимитом и reserve диска. FastAPI FileResponse поддерживает Range для плеера. Выгрузка CSV защищена от formula injection. Исходники архивируются в библиотеке без автоматического удаления файлов.

Пути из frontend не конкатенируются в subprocess. Папка для импорта читается только по явно заданному пользователем абсолютному пути; симлинки файлов пропускаются. URL только один HTTPS YouTube video ID; списки, встроенные в URL логин/пароль и другие хосты запрещены. Явно подключённая сессия YouTube хранится отдельно в `.secrets/youtube/` и передаётся yt-dlp через приватную копию файла, без значений cookies в argv/SQLite/HTTP. Данные транскрипта помечены как untrusted в AI prompt, structured response валидируется Pydantic и проверяется по длительности.

YouTube: `backend/youtube_auth.py` управляет отдельным обычным Chrome-профилем входа и отфильтрованной сессией; `workers/youtube_cookies.py` читает только этот профиль. `POST /api/import/youtube` создаёт постоянную задачу download с nullable source_id. `workers/youtube_fetch.py` выполняет один yt-dlp с Node/EJS, записывает ограниченные JSON-прогресс/результат. Farm следит за Pause/Cancel, сохраняет исходник через общий импорт и ставит анализ в очередь. Слияние потоков делит семафор FFmpeg с рендером. Кэш `.part` переживает паузу/перезапуск. Завершённый локальный источник и идентификатор следующего анализа checkpoint-ятся, чтобы Resume не скачивал и не анализировал повторно.

Расширение: реализовать `AnalysisProvider.analyze(...)` для OpenAI/local LLM; добавить миграцию схемы, если нужны отдельные модельные поля. Подпись семантического QC остаётся ручным решением, пока отсутствует проверенный независимый анализ.
